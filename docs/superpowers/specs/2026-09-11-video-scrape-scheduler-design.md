# Pexels 视频采集调度设计

## 1. 背景与目标

现有项目已经具备 Pexels 公共视频采集脚本，以及将采集结果写入 `platform_videos` 的导入流程。本次只增加调度和管理员手动触发能力：

- 每 4 小时自动采集一次。
- 每次最多采集并处理 50 条 Pexels 视频。
- 管理员可以通过 API 手动立即触发一次采集。
- 同一时刻只允许一个采集任务运行。
- 任务失败不应导致 Go API 服务退出。

本次不增加新的视频字段，不修改 Flutter 或 Vue 页面。

## 2. 方案选择

采用 Go API 进程内调度器 + 现有 Python Pexels 采集器 + MySQL 任务记录表。

### 选择原因

- 复用当前采集和入库流程，避免维护第二套爬虫逻辑。
- 手动触发、权限校验、运行锁和状态查询都可以统一放在现有 API 中。
- MySQL 记录任务历史，API 重启后仍能查看最近任务。

不采用 macOS `launchd`/系统定时任务，因为它无法自然复用 API 的管理员鉴权和任务状态接口。

## 3. 组件与职责

### 3.1 调度器

Go API 启动时创建一个 4 小时 ticker。首次启动不立即执行，等待第一个周期；管理员手动触发可立即执行。

调度器只负责产生任务触发事件，不直接处理视频数据。

### 3.2 任务执行器

任务执行器是定时触发和手动触发共用的唯一入口：

1. 抢占单实例互斥锁；若已有任务运行，返回“任务正在运行”。
2. 创建 `running` 任务记录。
3. 在 `services/api` 工作目录调用现有 Python 采集脚本，参数固定为：
   `--pexels --pexels-limit 50 --import`。
4. 读取脚本的 JSON 统计输出。
5. 任务成功时记录 `succeeded`；进程异常、超时、密钥缺失或入库失败时记录 `failed`。
6. 释放互斥锁。

脚本依赖的 Pexels 密钥继续从现有 `services/api/.env`/运行环境读取，不在代码或接口中传递密码和密钥。

### 3.3 任务仓储

新增 `video_scrape_jobs` 表，仅记录调度状态，不改变 `platform_videos`：

| 字段 | 用途 |
| --- | --- |
| `id` | 任务 ID |
| `status` | `running`、`succeeded`、`failed` |
| `trigger_type` | `scheduled` 或 `manual` |
| `started_at` | 开始时间 |
| `finished_at` | 结束时间 |
| `error_message` | 失败原因，可为空 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

视频仍使用现有 `platform_videos` 字段和 `(platform, external_id)` 唯一约束。重复视频执行更新，不把重复记录当作新增数据。

## 4. API 设计

### `POST /api/v1/admin/scraper/run`

管理员手动启动异步采集。

- 成功：`202 Accepted`，返回任务 ID。
- 未登录：`401 Unauthorized`。
- 非管理员：`403 Forbidden`。
- 已有任务运行：`409 Conflict`。

### `GET /api/v1/admin/scraper/status`

管理员查询当前状态和最近任务：

- 当前是否有任务运行。
- 最近一条任务的状态、触发方式、开始和结束时间、错误信息。
- 调度器计算出的下一次计划时间。

接口只提供调度状态，不改变视频查询接口的返回结构。

## 5. 生命周期与异常处理

- 每个采集进程设置超时，防止网络或子进程永久阻塞。
- 失败只更新任务记录，不终止 API 服务。
- 不自动重试；下一次 4 小时周期或管理员手动触发时再尝试，避免重复请求。
- API 重启时，将残留的 `running` 任务改为 `failed`，错误原因写为服务重启。
- 如果 Pexels 返回的视频已存在，继续按现有 upsert 逻辑处理。

## 6. 测试与验收

### 自动化测试

- 调度器能创建 4 小时周期，并能通过测试时钟触发一次任务。
- 手动触发和定时触发不能并发运行。
- 任务成功、失败、超时都会写入正确状态。
- 管理员、普通用户和未登录请求分别返回 `202`、`403`、`401`。
- 采集器命令固定包含 Pexels 来源和 50 条限制。

### 手工验收

1. 使用管理员 token 调用手动接口，确认返回任务 ID。
2. 调用状态接口，确认任务从 `running` 变为 `succeeded` 或 `failed`。
3. 查询 `platform_videos`，确认本次最多处理 50 条且无重复唯一键。
4. 在任务运行期间再次手动触发，确认返回 `409`。
5. 模拟缺少 Pexels 密钥，确认 API 仍可访问且任务记录为 `failed`。

## 7. 范围边界

本次不包含：

- 新增 Flutter/Vue 控制页面。
- 修改视频表结构或视频接口字段。
- 接入 YouTube、抖音、X 或需要额外授权的采集源。
- 自动重试、分布式锁和多实例调度。
